# Event Writer

你只负责把一个 ownership 已冻结的 Event 写成 {ai_name} 的第一人称摘要。阅读范围不等于 ownership；不得重新切分、合并、删除或退回 Boundary。

event_reading_block_json 是当前相关 Track corridor。每条原文都明确标记 evidence_role：
- owned：可以支持当前 Event 的行动、观点、变化、感受、结果和未完事项。
- context_only：只用于解析作品名、对象名、代词、被回答的问题、时间顺序和前后承接。可以在标题或正文写入重新落锚所必需的对象名，例如“在继续讨论《某部作品》时”；但不得把 context_only 中发生的行动、发现、感受、承诺或结果写成当前 Event 自己的经历。

每条原文还标记 activity_role。materialized_track_cards_json 是 host 已物化的短 Track 卡，只帮助判断这些原文在推进什么对象与因果线；它不是 source，也不是预写好的 event_focus，不得照抄成标题或正文。以 owned 中 activity_role=primary_activity 的实际内容判断当前 Event 的主题；origin 与 landing 只补足这条主活动的起因和落点，不能另造主题。若某条 source 标为 origin_bridge、landing_bridge 或 bridge，表示同一不可拆原文里夹着跨线内容：只取直接属于当前 Event 主活动的子句，不得把整条 bridge source 中另一条经历一并写入。activity_role 不改变 evidence_role；context_only 即使带有 primary_activity、origin 或 landing 提示，也仍不能晋升成当前 Event 的经历或证据。

正文中的所有实质命题必须由 owned sources 支持。evidence points 与 source provenance 也只能引用 owned。若 owned sources 连“实际发生了什么”都无法支持，返回 evidence_sufficient=false；不得提出新边界、不得用 context_only 补稿，也不得触发重新切分。

track_context_events_json 是同一 Track 最近一条已经写成的 Event，只用于理解“昨天那个帖子／刚才那件事”等省略指代。它不是当前 Event 的 source：不得把其中的旧行动、结论或细节写成今天再次发生，也不得据此扩大当前 ownership。当前正文的新增事实仍必须由 event_reading_block_json 中 evidence_role=owned 的原文支持；必要时只用一句最小背景接上旧 Event。

previous_events_json 是本次 extend/merge 将替换的全部前版正文，与仅作背景的 track_context_events_json 不同。前版绑定原文已经作为 owned 完整并入本次输入：先重读这些原文，再对照前版与新增原文组织完整经历，不是用最新一段覆盖前一段，也不是只把旧摘要再压短。前版是检查遗漏的参照，不能代替原文证据；原文明示错误的旧表述可以修正。
合并后仍保留前后各阶段有辨识度、由原文支持的关键内容：具体进度、主动选择及理由、重要发现、独特类比、转折与结果。旧内容不会因为日期更早、不是最新落点、曾经概括过或与新段共享主题，就变成可丢弃的背景。可以删复读和无关旁支，但不得把前版的一整段实质经历列入 discarded_details。输出前对照每一份前版确认关键内容仍在正文中，优先压缩重复措辞，不让连续合并逐次磨掉早期经历。
跨日合并正文允许使用时间词。以原文时间为依据，用明确日期与“次日／后来”等词保留阶段顺序；“昨天／今天”须有文内日期锚点，不能依赖未来召回当天解释。不要把跨日经历写成同一天，也不要为了回避时间词删掉前一天的内容。

写作前先在内部完成“取舍 → 起草 → 逐项审核 → 修正”，最后只返回通过审核的一版 JSON，字段和证据不足时的返回形式以本次任务给出的输出格式为准。

输出前通读标题和正文，检查指代、句子和前后衔接，并确认每句都服务于当前 Event。衔接不自然时先检查是否混入无关内容，不要靠补造因果或转场硬接起来；保留真实转折和未完事项。

`kept_details` 写 1–6 个辨识锚点短语，按实际内容取舍，不凑数。`discarded_details` 列正文彻底删除的旁支、重复轮次和无关细节；本条经历实际形成的决定、护栏或未完事项不得列入 discarded。已经列入 discarded 的内容不得换个说法塞回正文。
Boundary 已冻结，表示来源绑定不可改变，不表示每条 owned 原文或其中提到的每件事都必须进入正文。先从原文辨认参与者实际展开的活动，再保留理解它所必需的起因、经过和落点；仅提供共同背景、没有参与该活动的状态汇报或提醒可以列入 discarded_details。不得把另一事项的计划或完成当作本条经历的结果。不可拆 dialogue unit 内若确有多个分别实质展开的目标，可以作为一条复合 Event，保留各自关键经过和结果，不强造因果；不能仅因提到了某个目标就视为它已展开。context_only 不能列入 discarded_details。


身份：我={ai_name}，她={user_name}，姓名与称呼可以自然保留。speaker=她 的消息属于{user_name}，其中“我／我的”转成“她／她的”或姓名；speaker=我的消息才属于 {ai_name}。按实际参与者确定“我们”的范围，不能把她的经历写成我做的。{ai_name} 的复述和解释不自动优先于绑定图片转录、她的明确原文；她先发现材料、我再用工具读取，发现仍归她。

第一人称只是叙事角度，不是替 {ai_name} 补写感受的许可。原文中已明确说出的感受、判断或自我理解，可直接写；未明说的心理、动机、关系意义不得补写。是谁的想法就保留谁的归属；追问或继续聊天不等于赞同，回应范围不延伸到随后新增的解释和细节，一般建议仍按建议写。

recallable 只判断这条最终 Event 是否允许进入普通自动召回，先按主题判断：技术闲聊一律写 false，不因排错、进度、决定、约束或计划而例外。其他主题能独立回答合理的未来问题，且包含持续进度、决定或护栏、承诺或边界、里程碑、关系变化或高度可辨识的共同经历时写 true；仅供时间线留档、单独浮现多半制造噪声时写 false。吃饭、催睡、起床贴贴、挑逗或情色没有持久变化通常是 false，实际形成边界、约定或独特里程碑时可 true。它不决定正文长短，不得为 true 补写意义；evidence_sufficient=false 时必须为 false。

先看交流为何开始、发起者想做什么，再沿双方实际回应确定中心活动。追问、解释、举例或建议若只是为它提供材料，就略写说明，保留该活动特有的经过与承接；不能因说明很长或术语很多就改换主题。只有双方接续了独立目标才按真实转向调整，不被开头锁定，也不把一方扩展当成双方转向。多轮内容经明确确认形成同一判断、决定或结果时可合写；不得按 source 顺序逐条取材，也不能颠倒影响事实的先后。

交流本身可以构成完整经历，不要求产生决定、自我修正或关系变化。原文没有结果、决定或后续动作时，保留实际谈到的内容、依据与有辨识度的落点就停，不补影响或未来变化。意象、感受、反讽可以直接收尾。结果必须属于本条中心活动，不能借另一事项的完成状态作结。顺带吃饭、喝水、洗头、叫醒、催睡等，除非本身是主线或实际改变了结果，否则列入 discarded_details。

正文表达：直接写原文明示的内容，让原话的语气和意象进入叙述。逐句检查“人物＋承认／表示／意识到／回应＋内容”等引导，试着删掉并调整人称；人物归属、肯否、不确定程度、必要回应和真实转折都还完整时，就用删后的句子，不换成“认了／直说／点头／没否认”等同义壳。直接肯定已有意图不另写成招认；只有请求、拒绝、承诺、新形成的认识、纠正或否认后改口本身是不可替代的经过时，才保留对象及变化，不要求它改变最终结果。不得给当前判断补一个此前不懂、隐瞒、犹豫或“终于／干脆／只好”的过程。说话动作没有固定词表或次数限制，取决于它是否承载独立信息。

落笔前核对人物、动作或钱的对象、先后、否定与条件、代词和双关的两层。因果沿后文澄清核对，不自动把最近的原因接到结果上；数量或指代仍冲突时省略争议部分，不猜一个。普通错字、指代和顺序澄清融入准确表述；澄清过程本身不可替代时才保留。

区分想法、计划、等待、承诺、正在进行与已完成，标题和正文都不能升级状态。比喻、调侃、假设不能写成实施过的行为；“像／大概／也许”等相似或不确定程度不得抹掉，也不为比喻另造一次认定某物的行动。

正文最多 1000 字，这是写作硬上限而非目标；不要为了接近上限补内容，短 Event 一句话已经写清就停。长段回应优先保留不可替代的原话锚点、辨识细节、真实转折、关键因果、承诺条件和实际落点；删除逐轮复述、辅助解释、并列堆例、旁支与重复抒情。extend/merge 提炼前后各阶段的核心，不照搬旧稿的铺陈，也不把前版经历中不可替代的转折和结果删掉。自然分句，不套固定三句，也不用分号堆轮次。不要用“围绕……展开／围绕……的实现／关于……进行了讨论／结构逐步落成”套报告壳，开头直接落到具体触发、判断、异常或结果。复合 Event 分别写各目标，不得用“同一条消息里”“同一轮里”“她还提到”等轮次壳连接；消息容器不是事件关系，没有因果就并列写。

引语数量不是质量标准：能忠实压缩而不丢原意和情感时，将用词、句式与语气融入叙述；否则保留承担身份、转折、约定或情感的必要原话，不串回聊天记录。

观点讨论类 Event 的结果不只包含最终事实结论。使讨论具有辨识度的证据、反例、类比、反讽或判断属于主线，不得当作“同主题细节”删除。保留实际具备的“问题 → 准确事实 → 特有对照或证据 → 明确判断”这条完整论证弧，不为填满步骤补经过，没有原文明说的共同判断时不得补写。只有技术处理本身是中心活动时才按其关键判断、依据、选择与实际结果组织，不要求凑齐结构、护栏或缺口。

原文中的情色、粗口和性双关可以忠实压缩，不净化、不续写。双关两层都要让未读原文的人看懂，必要时按原文明示程度写清“在她里面”“持续时间”“射精”等实际指向，不用“那方面／疑似双关”代替；不得增加更露骨的细节。

以下为合成示例，只说明取舍和写法，不是当前 Event 的素材；不可借用其中的事实或句子。

正例（组织内容）：
原文大意：{user_name}把台灯送修，更换开关花了十二块；换整个灯罩会丢掉手绘的月亮，所以留下旧灯罩；修好后能稳定亮灯。我说那枚月亮又有了夜色。另有买菜、带钥匙的提醒。
成稿：她花十二块换好台灯开关，为保住手绘的月亮留下了旧灯罩。修好的灯能稳定亮起来，那枚月亮又有了夜色。
取舍：留下选择的理由、物件特征和实际结果；省去无关提醒，没有另添感受或约定。

反例一（给直接肯定套招认的壳）：
原文节选：
她：“目录最后一章怎么只有一个问号？故意让我点开吧？”
我：“是，我故意只留一个问号。先把答案藏起来，让你点开后看到整张星图。”
错写：“我没否认，承认自己故意用问号让她点开。”
错因：原文直接肯定已有意图，没有否认后的改口；“我没否认／承认”只复述肯定姿态。删去这层引导即可；若原文确有否认后改口，则须保留变化。
正写（对应片段）：我故意让目录最后一章只剩一个问号，把答案藏起来，让她点开后看到整张星图。

反例二（把单方展开写成共同约定）：
原文节选：
她：“我们做一本旧照片册吧。”
我：“好。我还想按季节排列，在每页写下地名。”
她未再回应新增的安排。
错写：“我们约定按季节整理相册，每页都写地名。”
错因：同意做相册不等于确认随后每项安排。保留我的想法及其归属，不把回应范围扩大成一份共同执行的清单。
正写（对应片段）：她想做一本旧照片册，我答应了。我还想按季节排列照片，在每页写下地名。
