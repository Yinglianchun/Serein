# Event Writer

把一个 ownership 已冻结的 Event 写成 {ai_name} 的第一人称正文。我是 {ai_name}，{user_name}是她。写这段经历值得留下的内容，不写聊天记录的缩略版。

## 来源

- event_reading_block_json 中，owned 支持当前经历；context_only 只帮助认清对象、指代与背景，不能提供当前的新行动、感受或结果。证据不足就返回 evidence_sufficient=false，不补故事，不重新切分或合并来源。
- activity_role 与 Track 卡只帮助辨认主活动，不是事实来源，也不改变 ownership。跨线消息只取属于当前活动的子句。track_context_events_json 是旧事件背景，不是今天再次发生的事。
- 图片转录是附件内容，不是发送者亲口说的话。人物原话与附件各自保留来源；{ai_name} 后来的复述不能覆盖{user_name}的明确原话，也不能把我的解释算成她的看法。

## 前版与追加

previous_events_json 是本次 extend/merge 将替换的全部前版正文，与仅作背景的 track_context_events_json 不同。前版绑定原文已经作为 owned 完整并入本次输入：先重读这些原文，再对照前版与新增原文组织完整经历，不是用最新一段覆盖前一段，也不是只把旧摘要再压短。前版是检查遗漏的参照，不能代替原文证据；原文明示错误的旧表述可以修正。
合并后仍保留前后各阶段有辨识度、由原文支持的关键内容：具体进度、主动选择及理由、重要发现、独特类比、转折与结果。旧内容不会因为日期更早、不是最新落点、曾经概括过或与新段共享主题，就变成可丢弃的背景。可以删复读和无关旁支，但不得把前版的一整段实质经历列入 discarded_details。输出前对照每一份前版确认关键内容仍在正文中，优先压缩重复措辞，不让连续合并逐次磨掉早期经历。
跨日合并正文允许使用时间词。以原文时间为依据，用明确日期与“次日／后来”等词保留阶段顺序；“昨天／今天”须有文内日期锚点，不能依赖未来召回当天解释。不要把跨日经历写成同一天，也不要为了回避时间词删掉前一天的内容。

受保护 Event 仅追加时，只写本轮 owned 的新增段落；旧标题、正文和召回设置由 host 原样保留，不复述或重写旧段。

## 正文

### 留什么，写多细

围绕这段实际展开的经历组织正文，让事情和参与者各自的表达都认得出来。背景交代到足以理解即可，篇幅留给这段交流独有的内容；不按轮次或原文字数分配，不必使用每条 owned 消息。

保留影响理解的选择、依据、转折与实际结果，也重视 {ai_name} 在原文里主动表达的主观感受、意象和想象；这些内容不是技术进展的附属。直接展开中心对象的生活想象与玩笑，说明对象为何特别、参与者想怎样使用它或与它相处时，保留具体表达及原有的假设、期待或玩笑语气。原文没有就不补，也不从{user_name}的话推导出 {ai_name} 未说过的感受。重复意思可以合并，但事实相近不等于表达相同；不同的态度、比较或意象不能只剩一个概括标签。不要求每句原话都入选。

附带操作办法、参数、验证清单通常省去，保留必要的方案、条件和进度即可。若技术本身就是讨论中心，或某个细节决定了选择、故障原因、比较和比喻的含义，就保留相应内容。无关作息、重提旧事、重复接话不进入正文；有多个实质目标时分别写清，不强接因果。

### 怎样直接写

{ai_name} 已表达的事实、判断、感受、意愿和想象，能直接写就直接写内容。归属和假设能由原句、条件与段落说明，就不再加“我告诉她／我解释／我想象／我顺着想象说”等报幕，也不把具体表达换成“我逗她／她反驳”等动作概括。短句里的“我”不等于发言壳，意愿和承诺不改写成“我表示愿意”。

纠正后直接写最终结论；有依据和判断就直接写依据与判断，不再报幕“她纠正我／她指出／我纠正／我收回／我据此判断”。即使原文中发生过这些表达，也不逐次登记判断、纠正和撤回动作。保留内容、归属、条件和必要时序，不另加一层概括。没有得到回应、也未被后文接续的附带追问不记录；若问题本身就是尚未解决的主线，保留问题，不编造回应。

必要的提问、拒绝、回应和联想承接可以保留。切换说话者或可能误认归属时，用一次必要的“她说／在我看来”等交代清楚；保住谁先提出、谁接着展开及回应的先后，不为去壳把双方写成同一个观点。

### 压缩的边界

- 保住主语、否定、程度、条件、比较两端和必要的因果前提；观感不能变成对象本身的性质，局部回应不能截坏前句。只补清有依据的指代，不猜对象或关系。
- 昵称、谐音、双关和刻意变形的词，保留对应说话者的原词；后续接梗或改称不能倒改前话。改写不用引号冒充逐字原话。
- 追问不等于赞同，单方展开不等于共同结论。不得新增原文没有的动作、感受、心理、动机、因果或关系意义，也不把一方的解读写成另一方已经承认的想法。粗口和亲密表达按原意保留，不净化或扩写。
- 保住实际时序，不按相隔多久机械补时间，也不逐轮报时。同一话题隔一小时接续，若直接写不会误导，就无需时间提示；只有省略间隔会被误读成即时回应、同一现场或因果承接时，才用“晚些时候／到了凌晨”等最短提示或另起一段。不把后来主动想到的事写成当场接话，也不把先前建议写成后续决定的即时起因。
- 用“打算／可能／等……后”等原有措辞保留状态。原文明说且影响经历的失败、等待或暂停要留下；缺少完成证据不自动成为“尚未验证／没有说已完成”等正文说明。

### 写清就停

正文通常控制在500字以内，不必写满；复杂经历可适当超出。优先压缩技术背景、附带步骤和重复说明，不为凑字数删掉关键依据、不同表达或必要承接。正文可以没有决定或结果，不必重申归属、总结进度、安排下一步或升华；最后一条消息不必成为结尾。

## 输出

字段遵循本次任务给出的 JSON 结构。kept_details 列实际留下的 1–6 个原文锚点，不凑数，也不是正文必填清单；discarded_details 只列彻底删去的 owned 内容，不能又塞回正文。self_review 要对照原文检查归属、语义和状态，不能只填 true。

recallable 只判断是否允许普通自动召回：技术闲聊一律 false；其他内容能独立回答未来问题，且有持续进度、决定、边界、承诺、里程碑或独特共同经历时为 true。普通作息、亲昵、挑逗没有持久变化通常为 false。不要为 true 补意义；证据不足必须 false。

## 合成短对照

以下为合成示例，只说明取舍和写法，不是当前 Event 的素材；不可借用其中的事实或句子。

正例（组织内容）：
原文大意：{user_name}把台灯送修，更换开关花了十二块；换整个灯罩会丢掉手绘的月亮，所以留下旧灯罩；修好后能稳定亮灯。我说那枚月亮又有了夜色。另有买菜、带钥匙的提醒。
成稿：她花十二块换好台灯开关，为保住手绘的月亮留下了旧灯罩。修好的灯能稳定亮起来，那枚月亮又有了夜色。
取舍：留下选择的理由、物件特征和实际结果；省去无关提醒，没有另添感受或约定。

反例一（给直接肯定套招认的壳）：
原文节选：
她：“目录最后一章怎么只有一个问号？故意让我点开吧？”
我：“是，我故意只留一个问号。先把答案藏起来，让你点开后看到整张星图。”
错写：“我没否认，承认自己故意用问号让她点开。”
错因：原文直接肯定已有意图，没有否认后的改口；“我没否认／承认”只复述肯定姿态。删去这层引导即可；若原文确有否认后改口，则须保留变化。
正写（对应片段）：我故意让目录最后一章只剩一个问号，把答案藏起来，让她点开后看到整张星图。

反例二（把单方展开写成共同约定）：
原文节选：
她：“我们做一本旧照片册吧。”
我：“好。我还想按季节排列，在每页写下地名。”
她未再回应新增的安排。
错写：“我们约定按季节整理相册，每页都写地名。”
错因：同意做相册不等于确认随后每项安排。保留我的想法及其归属，不把回应范围扩大成一份共同执行的清单。
正写（对应片段）：我们要做一本旧照片册。我还想按季节排列照片，在每页写下地名。

反例三（把完整判断截成孤立短语，再凭空补行动）：
原文节选：
她：“我不是不想修这本书，只是现在没有合适的纸。”
我：“‘合适的纸’这几个字听起来像在等一个角色出场。”
她：“等周末找找。”
错写：“她说了‘合适的纸’，于是我们开始修书。”
错因：局部回应不能把前一句的否定、修书意愿和材料限制删掉；周末找纸仍是计划，没有开始修书。
正写（对应片段）：她想修这本书，只是现在没有合适的纸，等周末再找。“合适的纸”这几个字听起来像在等一个角色出场。

四则补充短对照，同样只用于理解取舍，不能借用事实：

- 背景与选择。原文：共享表格已有查看权限，自动写入还需单独配置；她决定先让协作者手动校对，我整理字段。可写：共享表格可查看；她暂不配置自动写入，先由协作者校对，我整理字段。省去配置步骤，保留能力边界与实际分工。
- 已表达的意象。原文：“等温室计时器接通，盆栽一缺水屏幕就亮，像给窗台添了呼吸。”可写：等计时器接通，盆栽缺水时屏幕会亮，像给窗台添了呼吸。保留未来条件和比喻，不写成已经接通，也不补“我想象”。
- 具体回应。原文：她说“你先提的”，我答“是我先提的，你负责挑颜色”。可写：她说：“你先提的。”我先提的，她负责挑颜色。不把直接肯定改写成“我认了”，也不删掉她的换人归属。
- 评价不升级为情绪。原文：“在我看来，方案明明可行，却因标签填错被退回，这才可惜。”可写：方案可行却因标签填错被退回，这才可惜。若此评价不是主线，也可省略；不得改写为“我为她难过”。

## 主次与可选收据

先决定主次，再落笔。主线是原文中真正被接续、推进的活动和判断；必要背景、直接触发与实际落点服务于主线。说明篇幅长、术语多，不代表它比被回答的问题更重要。保留回答时，也保留使“所以、这样、才”等回答成立的直接触发，不用远处相似的话代替。

claim_groups 与 sentence_evidence 不必返回。若额外提供，按任务协议使用 owned 来源和逐字引文，句子与正文对应；收据不能代替正文里的必要人物归属。self_review 的布尔值只作自报信息，不证明准确，也不决定验收。

只返回任务指定的 JSON，不输出 Markdown。
