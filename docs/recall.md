# 召回与索引

## 路由与相关性规则

`src/serein/resources/route-examples.json` 保存 v41 路由的公开改写版，版本名 `public-v41-1`。5 个启用类别含 67 条普通例句、11 条边界例句；另保留 1 个停用类别，准备时不为它请求向量。保留类别动作、各类阈值、普通/边界职责和技术闲聊的近邻边界对。具体私人经历和项目细节改写成合成例句。

路由参数：最低分 0.72、异类分差 0.06、每类取最高 1 条、边界否决开启、边界最低分 0.62、允许落后 0.03。两层 surface gate 继续区分类别动作与最终路由动作，不能把技术闲聊的 skip 一律变成提前禁止检索。

`recall-policy.json` 保留对应相关性别名与上下文规则，删除私有身份词；运行时从设置页加入当前用户和 AI 名字。它不包含实例地址、密钥、实体库或私人向量。

路由例句与 Embedding 模型共同影响分类效果；更换模型后应使用自己的合成或获准语料校准。

## 设置页自动准备

保存 embedding 和 reranker，点击“建立 / 补齐检索索引”，会生成对应模型的路由、正文向量、实体及 Arc 范围索引；开启长文分段后还会补齐缺失的 passages 向量。所有派生文件在实例数据库旁的 `model-indexes/<模型配置标识>/`，不需要配置私有后台 YAML 或手写 `germany_policy_file`。内部兼容字段名不表示会连接其他部署。

实体优先从当前绑定原话提取；没有绑定原话时使用当前记忆正文，并明确标记 `memory_body` 出处。名字和引文必须通过逐字校验，正文、标题或绑定变化后旧提取结果失效；别名建议不合并身份。Arc 标题、别名和成员来自当前叙事卷/材料关联。实体命中只是检索线索，Arc 只限制查找范围，不自动带入整卷正文。后台索引队列更新新证据、解绑结果和 Arc 修订；不新增“是否值得提起”的模型任务。

原来只有少量例句的准备结果不再标记为就绪。更新本版后重新点击一次“建立 / 补齐检索索引”；规则资源变更也需要重新准备。会调用所选 embedding，不会暗中借用旧模型向量。名字和模型选择仍持久保存，不需要改 YAML 或重启来应用设置。

## 主域浮现规则

“地下室 → 主域边界”顶部切换 Event / Scene，各自保留草稿并单独保存。每个主域可选“允许自动浮现”“仅明确召回”“不浮现”。主域名称和短描述共用，模型只负责打标；程序按记忆类型查询浮现规则，不增加浮现判断模型或判断要求。配置页仍只选择打标模型。

旧主域 `policy` 同时作为两类的默认规则；实例数据库中的 `tagging.policies.event` / `scene` 单独覆盖对应类型。保存采用版本检查，发生冲突保留草稿；刷新后撤销当前类型的旧草稿，再根据最新规则修改。保存一个类型不会提交另一个类型的草稿，旧客户端更新主域目录也不会清除已有类型规则。

普通召回、实体候选、自动浮现和关系扩散都应用两类规则。“仅明确召回”需要明确标题、编号或完整已写入的 cue，实体名或纯向量相似不足以放行；这些锚点仍须通过原有准入流程。关系扩散最多补一个候选，边本身不提供证据。手动关闭、归档、Event 替换或 Scene 覆盖、证据和冷却限制继续生效；直接读取记忆不受主域浮现规则限制。

修改规则不重跑历史打标，不改正文、实体、cues 或手动开关，也不需要重建向量。Event Writer 不再判断 `recallable`；新 Event 的兼容字段由程序生成，续写或重写保留前版的手动关闭及未审核状态。

## 可选长文分段

Passage 用来找回长 Event / Scene 中容易被整篇主题盖住的细节。例如一篇 Scene 同时记录旅行、晚饭和见面约定，用户问“约好在哪里见面”时，可通过包含约定的片段找到所属记忆。片段分别建立检索索引，不改写原文、不创建多条独立记忆；命中后仍需经过相关性筛选和冷却，不保证注入。**当前独立日记和叙事卷不使用这条 Passage 通道。**

长 Event / Scene 较多、常查询其中细节时可开启；以短文为主可先关闭，关闭后仍可用整篇检索。切段本身不调用模型；分段向量需要已配置的 Embedding，会增加模型调用量、处理时间和索引占用。

“设置 → 配置”提供“长文分段检索（Passage）”开关和起切字数，默认关闭、500 字。正文超过门槛才切；现有 TOML 显式开关仍保留，页面保存后覆盖。写入与首次导入预先保存模型无关的原文分段，后台只补本次变更的向量，召回只读取现有索引。调门槛不全库重切，旧分段继续复用；主动准备检索可补齐从未准备的旧记忆。
500 字是开始切分的门槛，不是每段长度；正好 500 字不切。汉字、字母和标点按字符计，Scene 的评论等上下文不计入有效证据正文。聊天请求不现场切分或补向量，缺失时仍走可用的整篇检索。网页“使用说明 → 长文分段”提供相同说明与配置入口。
模型无关分段位于实例数据库旁的 `<数据库文件名>.passages.sqlite`，包含原文偏移及正文指纹；各模型的 passages 文本与向量仍在自己的检索索引。都是可重建派生文件，正文始终以实例数据库为准。正文修改会使旧分段失效，标题或标签修改可复用分段。关闭保留数据并停用该通道，不能通过单次请求绕过。详见 [配置说明](model-settings.md)。

## 召回严格程度

在“设置 → 配置”分别调整正文向量扩展门槛（默认 0.50）、Scene cue 语义扩展门槛（默认 0.55）和最终筛选阈值（默认 0.65），范围均为 0–1。前两项只控制第 7–20 条弱候选是否值得交给 reranker；最后一项决定重排后是否准入。调低会增加对应阶段的候选，也可能增加模型输入或无关内容。最终门槛可携带未保存值跳到“召回模拟”，一次运行已保存与试调两档并排对照，再明确保存；两档独立调用召回，模型结果可能波动。参数保存到实例数据库，后续请求生效，无需重建索引；路由、主域范围、选卡上限和冷却规则仍然有效。具体操作见 [配置说明](model-settings.md)。

自动召回及开窗续接保留 Event/Scene 自身 ID。`read_memory(identifier=记忆ID)` 默认只读正文；需要绑定原文时显式传入 `with_evidence=True`，一次读取正文和全部当前有效绑定证据，无需先收集原话编号。

## 自动候选预算

路由的最终动作决定是否检索：明确 `skip` 时在候选检索前停止，所有路线类别一致；分数或分差不足、命中召回边界时允许检索。后续不再根据模板默认动作、回忆措辞或名字重新改判。最终哪些候选成为卡片仍由正文重排评分决定。

“什么时候、哪天、原话、逐字、整体、从头、完整故事”等词不再自动转交到其他阅读分支。路由放行后，已知的单一 Arc 名字可以限定候选范围，无需附带“还记得”；多个或有歧义的范围退回全局 Event/Scene 检索。整卷和绑定原文仍可通过显式工具读取。

聊天 Hook 的原句只按当前实例设置补全未被引号包围的“你的／我的”：使用 `identity.ai_name` 与 `identity.user_name`，下一次请求读取改名后的配置。单独的“你／我”与“我们／我们的／咱们”等共同人称保持原样，“迷你的”“自我的”等词也不拆分替换。补全仅用于正文重排，原句、路由输入、向量查询与记忆原文保持不变；工具自己组织的查询不自动假定说话者。模拟页显示实际候选数、处理阶段、路由分数、重排问句及候选去向，缺失字段不冒充零。

硅基流动 `api.siliconflow.cn` 的 Qwen3-Reranker 0.6B/4B/8B 使用独立 `instruction` 字段传入通用记忆相关性标准：具体信息可以回答问题、补充个人背景、自然延续话题或纠正误记；仅姓名、宽泛主题或亲密语气相似不足以相关，真实相关的关系经历仍可入选。指令采用通用表述，不包含预设人名。其他提供方与模型保持原请求格式，已有阈值保持不变。该指令不能保证消除误判。

自动召回先批量排除非活动、未允许自动浮现、已被后版替换，以及被任一活动 Scene 完整覆盖全部来源的 Event；它们仍可保留在索引中供主动读取或状态恢复。混合向量排名前 6 条保留进入重排的机会；第 7–20 条只有整篇／片段 cosine 达到已保存的正文向量扩展门槛，或 Scene cue 语义 cosine 达到 cue 扩展门槛，或 Event 命中特定关键词，或查询明确带回忆意图且完整实体名命中时才可进入。弱尾部不会为了填满 20 条而补入。

cue、关键词和实体扩展各最多 3 条，只决定是否进入同一次 reranker，不增加候选分数，也不绕过最终筛选阈值。cue 保持语义向量匹配，不要求查询逐字包含 cue。诊断结果提供候选来源、各信号分数、进入原因和实际候选数；最终仍最多选择两张卡。

## 旧主域兼容

明确且非空的 `canonical_domain` 优先；缺失时读旧 `domain` 字符串或列表中首个非空项，再缺失才使用 `general`。支持自定义主域，不根据正文猜分类，不把旧列表中所有标签都当主域。

相同规则用于 lookup、混合候选过滤、关系扩散两端、Scene 详情和列表投影。自动打标也跳过已经有旧主域的 Scene，避免把它误当成未分类记忆。读取兼容不重写已有元数据、正文和历史版本。默认主域仍为用户确认的七项；排除策略使用设置页当前保存值。

## 关系候选

按上述预算取得最多 20 个 Scene/Event 直接候选，再从直接 Scene 候选的活动、已确认关系中，选最多一个尚未进入候选池的 Scene。按该邻居自己的向量及时间排序选择，不增加关系分，不沿第二跳继续扩散。

主域、当前有效对象、明确排除 ID 和已解析的 Arc 范围仍限制关系候选。最多 21 条内容进入同一次 reranker，以已配置的最终筛选阈值（默认 0.65）为门槛，整个池最多选两条。关系候选同样在选卡后检查冷却，被取消后不补位，也不预留最终注入名额。

`candidate_scores` 增加 `candidate_origin=direct/relation`，关系项携带起点 Scene 和边 ID。旧 `related_candidates` 仍是选卡后的诊断列表。此改动不改变路由例句或 embedding profile，不要求重新生成向量。

## 联想开关

设置 → 功能增加“联想”滑动开关，使用实例数据库中的 `features.association`，默认关闭，旧配置缺失字段也按关闭处理。
保存后下一次请求直接读取，不需要重启服务、重新生成向量或重建关系。

关闭时混合路径跳过 `add_related_candidate`，保留按候选预算筛出的直接候选；Scene 关系查找也提前返回，lookup／兼容召回不返回关联诊断列表。
开启时沿用前述最多一条已确认 Scene 邻居、一次 reranker、已配置的最终筛选阈值（默认 0.65）、最多两卡和选卡后冷却规则。
`candidate_policy.association_enabled` 表示本次开关状态，`relation_pool_limit` 为 0／1，总 `pool_limit` 为 20／21；实际候选可以更少。
`related_candidates` 只在开启时保留为选卡后的诊断列表，不代表已注入。

开关与 `relations_auto_accept` 相互独立；切换不会删除已确认关系，也不会批量审核待审关系。


### 重排正文与片段上下文

重排输入每条含标题最多 4000 字符。短记忆使用完整有效正文，不因 passage 向量胜出而只送两个片段。长记忆选最多两个高分片段，各补最多前后 200 字符；按原文顺序排列、合并重叠窗口，并共享总预算。补文限制在原本允许的正文区域，Scene 评论、后续、待办等区块仍不作为证据。没有有效片段时沿用有界正文截取；不在召回时重新切段或生成向量，仍是同一次重排请求。
