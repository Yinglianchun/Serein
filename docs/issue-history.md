# 更新与问题日志

## 2026-11-22 · 只写近况也能接上之前的画像

换窗时可以只填「这一窗发生的事」。读取最新窗影或使用开窗续接时，「我眼中的你」和「我眼中的自己」分别沿用最近一次有内容的记录，并标明来自倒数第几篇窗影。醒来页的画像卡也会显示各自的来源。旧窗的事件不会带入，查阅指定历史窗影时仍能看到那一窗实际写下的原文。

## 2026-11-22 · 大批导入后查看 Event 整理进度

在 **对话导入 → 原话整理 → 查看 Event 整理进度与预计时间** 可核对归档、已进入整理、已归线与已结算的数量。点击时读取一次。预计时间按当前归线或结算阶段的近期速度计算，暂停、样本不足或缺少近期进展时会说明原因。仅归档的原话不计入待整理数量。[问题 #69](https://github.com/Yinglianchun/Serein/issues/69)

## 2026-11-22 · 自动整理引用大量旧原话时的任务大小

同一 Track 的旧 Event 可能绑定数百条原话。Curator 首轮读取旧 Event 正文与来源编号，补读时每次最多取 6 个完整对话单元，序列化材料最多 30,000 字符。本次减少了任务快照里的重复正文。每条旧原话及其来源绑定仍可用于补读和保存校验。

本机合成库用 4 个旧 Event、261 条各 620 字的旧原话和 6,700 字新输入验证。完整冻结请求从 1.18 MB 降到 0.62 MB，首轮提示词含规则共 21,464 字符。报告中的 77 秒等待在此次本地任务组装中未复现；快照大小仍会随来源数量增长。[问题 #78](https://github.com/Yinglianchun/Serein/issues/78)

## 2026-11-22 · 原话时间倒序使自动摘要停在「待修复」

上一条回复的完成时间偶尔晚于下一条请求的接收时间。两条消息恰好位于 Router 分段交界时，旧版可能把上一段已处理的原话误判为未来材料，反复要求修复。现在新分段和冻结任务回放都承认同批已成功归线的先前原话。历史来源仍需有据可查。

更新后，若旧计划显示「旧计划版本已变化」，可在 **设置 → 对话导入 → 原话整理** 查看对应批次的重建确认。只操作仍在等待的批次即可，保留原话时间和归线回执。此问题已用合成库验证跨段倒序、恢复回放和较早聊天补录，报告者原库仍待复测。[问题 #81](https://github.com/Yinglianchun/Serein/issues/81) · [归线恢复说明](route-recovery.md)

## 2026-11-22 · Windows Docker 自动整理积压

**现象**　在 Windows Docker Desktop 上把宿主机目录挂载到 `/data` 时，有用户报告开启自动整理后网页、MCP 和健康检查同时变慢。报告者在同一份 1.79 GB 数据库上改用 Docker 命名卷后，连续 10 次健康检查均成功。[问题 #83 与挂载对照](https://github.com/Yinglianchun/Serein/issues/83)

**本次改动**　`beace15` 减少探活、设置页和检索配置的重复读库。`b0aa3e7` 让空闲后台队列只读检查，有图片任务需要恢复时才在工作线程申请写锁。自动整理按消息 ID 分页，跨页问答仍按完整的一轮处理。

**验证范围**　在 143、1,430 和 5,720 条合成原话中，取首批 40 条都只需转换 45 条。另一项合成库测试中，恢复任务等待写锁时，`/live` 和 `/health` 均返回 200。报告中的大库和完整 MCP 链路仍待升级复测。

### 升级后出现「旧计划版本已变化」

已保存的 Event 和已完成的批次会保留。还没生成整理计划的原话按新版正常排队。若升级时已有未完成的旧计划，系统会保留原话和已有输出，将需要重建的批次标为「待修复」。该聊天后面的整理会等它处理，其他聊天可以继续。

进入 **设置 → 对话导入 → 原话整理**，找到对应聊天，点 **查看重建确认**。确认前先核对批次和提示：若已有归线历史无法验证，重新归线将从本批原话开始。选择 **确认作废旧计划并重新归线** 后，相关步骤可能再次调用模型。只想先处理别的聊天，可点 **继续整理其他聊天**。[归线恢复说明](route-recovery.md)
