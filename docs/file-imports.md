# 对话与 Operit 记忆导入

进入设置的“导入”页签，在“原话整理 → 对话与记忆导入”选择文件或拖入文件，核对类型、条数和正文预览，再点击“开始导入”。一次选择一个 UTF-8 文件，最大 32 MB；更大的导出请按会话拆分，酒馆的长会话可按下面的消息行规则分段。预览会保存待导入任务，但不会把内容写成原话或 Scene。

## 聊天记录

支持以下文字导出：

| 文件结构 | 处理方式 |
| --- | --- |
| Claude：会话对象或数组，含 `uuid`、`chat_messages` | 保留会话边界、消息 UUID 和时间 |
| ChatGPT：含 `mapping`、`current_node` 的会话对象或数组 | 只导入当前分支；多分支且缺少 `current_node` 时拒绝猜测 |
| SillyTavern（酒馆）：JSONL 首行聊天元数据，后续每行一条消息 | 按 `is_user` 区分双方，读取当前 `mes` 正文和 `send_date` 时间；一份导出是一段会话 |
| DeepSeek / 通用 `messages` JSON | 读取 `role`、`content`，支持会话对象数组或 `conversations` 包装 |
| `events` JSON、消息对象数组、每行一条消息的 JSONL | 使用显式 `session_id` / `conversation_id` 区分会话 |
| Markdown / TXT | 识别 `User:`、`AI:`、`用户：`、`助手：` 等角色前缀，以及设置页中的双方名字；无前缀视为一条用户文本 |

可用 [通用对话示例](../examples/conversation-file.json) 查看格式。只把用户和 AI 的文字消息放入原话档案；系统、工具及没有文字的消息会跳过，并在预览中给出数量。图片和附件不下载。消息原始对象保存在元数据中；归档仍遵守现有客户端注入上下文清理规则。缺少时间会标记“原始时间未知”，使用首次导入时间归档。

同一会话的原始消息 ID 用于去重。重复 ID 的内容改变时报告冲突，保留已有原话。没有会话 ID 时根据导出内容生成标识，没有消息 ID 时使用会话内位置；因此修改、裁剪或重新排列这些缺少 ID 的导出，可能被识别为新会话。不要把这种情况当作跨文件自动去重。

酒馆的 `is_system` 也可能标记隐藏的聊天消息，因此仍按 `is_user` 保留其原话，在预览中提示隐藏消息数量。只读取 `mes`，不把 `swipes` 的其他回复、续写历史或 `extra.reasoning` 追加到正文；这些字段及插件附加数据完整保留在消息元数据中。首行原始聊天元数据另存于导入任务的 `sillytavern_header`，不当作一条消息，也不作为提示词执行。

酒馆优先使用 `chat_metadata.integrity` 识别会话；旧导出可使用 `create_date` 加双方导出名称。没有消息 ID 时，使用 `send_date`、角色及同时间的出现顺序识别消息；同一会话且消息标识未变时，重新导出或分段导入可去重，同一标识的正文变化报告冲突。若重生成或切换备选同时改变了 `send_date`，且消息没有固定 ID，会被视为新消息。单段超过 32 MB 时，可按完整消息行拆分，每段开头保留同一份首行元数据，按原先后顺序导入；同一角色、同一时间的多条消息须全部留在同一段。缺少会话标识或消息时间时，预览会提示无法可靠跨段去重，应保留完整导出，不要依赖裁剪后的自动去重。滑窗仅影响酒馆每次发给模型的上下文范围，不改变导出文件的会话归属和历史原话。

导入历史默认只归档，不加入自动归线／Event 整理积压；仍可搜索、读取、手动绑定为证据。自动整理从后续新增聊天开始。按每条消息的导入归属识别历史，不用全库最大 ID 或时间截断，因此导入期间到达的新聊天也保留整理资格。旧库迁移原话遵循相同边界；升级后已导入但尚未整理的文件历史也退出自动任务。若旧批次混有历史与新聊天，只退役该批计划，新聊天重新选批，已生成的记忆和证据不改。

聊天文件导入完成后，可选择“立即从头摘要（后台）”：解除该文件的历史边界并提交后台整理任务，无需开启自动摘要。复用现有整理队列，也会处理其他已开放的待整理原话；模型未配置时等待配置或 Agent。原话不再次导入，已完成的摘要不会重做，可能产生模型费用。也可选择“暂不处理，并推游标到最后一句”：保存该文件的跳过边界，原文保留，不移动全库游标或跳过其他聊天。之后仍可点击从头摘要。不会自动生成 Scene，也不会替其他文件解除边界。

## Operit 记忆库

支持含 `exportDate`、`memories`、`links` 的 Operit JSON 备份，示例见 [Operit 备份](../examples/operit-memory-file.json)。导入内容保存在当前实例的 Scene、原文与索引存储中。

每条记忆的正文原样保存为 Scene，不改写成摘要。UUID 决定稳定的公开版 ID；相同 UUID、相同正文跳过，相同 UUID、不同正文报冲突，不覆盖。原始标题、标签、文件夹、时间、来源、重要度等字段保存在 `operit_original` 元数据中。时间戳保留实际时刻，Scene 日期沿用旧导入的 UTC+8 日历日。原文来源明确标为 Operit 记忆，不冒充聊天消息。

旧关联保留在导入任务中，不直接转成公开版已审核关系；旧向量不带入。正文会进入当前索引队列，配置检索模型后使用本实例的向量空间建立索引。旧重要度不会直接变成新的召回权重；cues 由下面的可选打标步骤生成，不照搬旧标签。

默认勾选“Operit 导入后自动打标”。在“配置”页签为“打标”选模型后，完整文件入库，再并发处理至多两条，标主域边界大标签，并在同次请求中提取带准确出处的实体，不生成小主题词或改写正文。默认主域为关系、亲密、内在、生活、技术、项目、通用。在地下室的“主域边界”点击“添加”打开弹窗，也可以编辑名称、短描述或移除主域；设置页不再有“主域”页签。保存到实例配置后，每次新的打标请求都会读取完整目录（key、名称、短描述和召回策略），无需重启；已有标签不会自动重打。新主域同步用于记忆详情和召回边界。模型留空时任务等待，原文仍可读；不需要打标可在选择文件前关闭。失败最多尝试三次，页面可刷新结果或点击“重试打标”。导入后被编辑的正文会跳过自动打标。原始标签始终保留在原始元数据里。

同一个“打标”模型也负责普通 Event / Scene 尚未指定的主域和实体提取，以及长 Scene 已有 cues 与 passage 的绑定。绑定沿用连续原文证据校验，无法支持的 cue 保持未绑定，不生成新 cue；向量仍使用单独选择的 Embedding。需开启长文分段、已有 passage 索引并准备好检索后才执行绑定。起切字数在“设置 → 配置”调整，默认 500；首次导入时保存分段，重复导入不重切。更换打标模型会重建相关派生绑定，不改 canonical 正文。

Operit 导入的 Scene 在同一次打标请求中补充 `scene_cues`：根据当前正文提取 1–6 个具体经历线索，每条 2–60 字，禁止出现配置的用户／AI 名字及 User/AI 占位称呼；没有可靠线索可返回空数组。模型仍返回含禁用名字的 cue 时，程序只丢弃该条，保留同批其他合格 cues，不为此重试模型；其他格式校验失败才保留原文并等待显式重试。已有 cues 不覆盖；空结果也记录完成，避免反复调用模型。此前已选择自动打标、但只完成主域和实体的 Operit 记录会补跑一次；未选择打标的记录不补跑。生成后进入已有检索索引及段落绑定流程。

导入的历史对话默认仅归档，除非明确加入整理，否则不自动形成 Event。后续新增聊天经自动整理形成的 Event 不生成召回 cues；其自动打标只补主域和实体。旧流水线留下的 `suggested_cues` 仅作整理明细，不作为 Event 的召回字段。

## 进度和 API

后台每批落库最多 25 条，进度与预览存入本实例数据库。离开页面继续运行，回来恢复当前阶段和真实计数；点击暂停会在当前批次保存后停止。服务重启导致的中断会显示出来，可继续。重复点击不会启动两份同一任务。错误条目显示序号；其余成功条目保留。已完成且有冲突的文件需在导出侧修正问题后重新选择，不能用“继续”覆盖已有正文。同一文件重复选择会回到原任务。

HTTP 接口要求实例 token：

- `POST /v1/imports/preview`：JSON `{filename, content, mode: "auto" | "conversation" | "operit", tagging: true}`。
- `GET /v1/imports`：最近十个任务、进度及打标状态。
- `POST /v1/imports/{id}/continue`：提交或复用后台任务，立即返回任务状态；用 GET 读取进度和 `failed`，浏览器不再循环推进。
- `POST /v1/imports/{id}/pause`：保存当前批次后暂停。
- `POST /v1/pipeline/next`：后台整理所有当前可处理的小批。
- `GET /v1/pipeline/status`：当前阶段、计数、暂停批次、失败图片和模型尝试记录。
- `POST /v1/pipeline/retry-batch`：传 `{batch_id}` 恢复暂停批次，从未完成步骤继续。
- `POST /v1/pipeline/retry-image`：传 `{sha256}` 重新开放该图片的三次转录机会。
- `POST /v1/imports/{id}/summarize`：释放已完成的聊天导入并立即排队后台摘要。
- `POST /v1/imports/{id}/skip-summary`：保存该导入的末尾边界，不调用模型。
- `POST /v1/imports/{id}/include-in-events`：明确让已完成的聊天文件导入参与 Event 整理。
- `GET /v1/pipeline/attempts/{id}`：下载指定模型返回与校验错误。
- `POST /v1/imports/retry-tagging`：将失败的打标任务重新排队。

此入口只处理用户选择的导出文件，不扫描旧数据库或私人目录。旧库一键转换、原文库替换与旧部署清理不在此功能中。

实体提取覆盖范围、别名建议和修改后的失效规则见 [实体提取](entity-tagging.md)。

整理输入先按 20 分钟沉默切块，无原始时间则按 20 轮完整问答切块，保留原编号和完整问答。默认每批新原文目标 40000 字符、完整模型提示词上限 200000 字符，模型读取超时 600 秒，在“配置 → 自动摘要配置”调整。编号或 JSON 错误可带诊断纠正；文字步骤累计失败三次暂停，同一聊天等待恢复，其他聊天继续。不合格返回保留作诊断，不写入正式 Event。完整规则见 [功能约定](public-feature-contracts.md)。
