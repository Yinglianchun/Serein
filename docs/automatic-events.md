# 自动 Event

自动整理采用归线 → 切分 → Event 写作三个语义阶段，不再单独调用原话证据整理。图片转录是可复用的材料预处理：选择“图片转录”模型后，它会先按原图字节生成转录并写回原始消息；未选择时仍由 Curator 直接读图、随切分结果返回转录。Event 直接保存到记忆库。公开版还可以为“Event · Arc 归档”选择模型，使以后落库的 Event 自动归入最多一条已有叙事卷；留空则不开启。如需把 Event 写成 Scene，可另行开启“Event 升为 Scene”，由聊天中的主模型读过原话后编辑并保存，不会自动执行。原话编号、来源绑定与哈希、图片转录和 Writer 自检继续保留。

## 可选的 Arc Linker

`Event Writer → 正式 Event → 自动归入已有叙事卷`。Event 结算完成后，程序只用它的标题和正文在活动 Arc 的标题、别名、实体和检索词中做关键词预检索，再把有界候选交给 Arc Linker。Linker 只能选一条已有 Arc 或返回不归属；不创建 Arc，不写叙事正文，不读 Event 绑定的聊天原话或叙事卷正文。

Arc Linker 直接根据 Event 内容与 Arc 卡判断，不等待、不使用打标模型抽取的 `tagged_entities`。关键词没有命中任何 Arc 时不调用模型；模型或格式失败时 Event 仍已正常落库，只保持未归属。这是落库后的可选任务，不改变前面三阶段的结算成功与否。

升级时忽略旧的 `event_evidence` 模型选择；旧页面提交该字段仍可保存其他配置。停在该阶段的任务继续时直接进入 Writer，已完成的归线、切分及历史回执保留；历史 Event 的旧证据整理结果不删除。

公开版聊天代理在收到成功回复后，把当前用户原话和完整助手正文写入消息库，使用已有的原话编号、搜索与流水线待处理入口。流式响应必须正常结束；工具调用阶段只保存用户原话，最终正文回来后补齐助手消息。系统提示、推理、工具返回和注入材料不作为原话归档，图片保留材料引用。关闭自动摘要或记忆召回不影响原话保存。

客户端应传稳定的 `serein.window_id` 或 `X-Serein-Window-Id`。重试和工具续轮按窗口及原始对话去重；提供消息 `id` / `message_id` 时，裁剪历史后仍可识别同一消息。没有消息 ID 的客户端若同时改变历史，无法可靠识别其是否为旧请求；不同窗口也不应共用默认的 `main`。时间记录为代理接收/回复完成时间，不伪造历史消息时间；不会自动补录请求携带的旧聊天。入库失败或内容被拒绝会记在请求诊断的 `raw_archive` 中，不丢弃已经生成的回复。

自动摘要开关在设置 → 功能中，保存后生效。点击“自动摘要配置”跳转到配置页，选择执行方式和参数。三个语义阶段分别为归线、切分、Event 写作，也在“配置”页选择模型；图片转录可另选模型并在聊天与自动摘要之间复用。“模型”页管理上游地址、密钥和模型目录；打开时直接显示已配置上游，各上游里的模型和编辑项默认收起。

打开开关不会立刻或每轮固定调用三个模型。聊天成功后先保存原话，不调用整理模型；文件导入和旧库迁移的历史原话只归档，不进入自动 Event 队列。白天同一会话累计至少五个已完成回复包，并在最后一条可回应消息后静默二十分钟，才按批调用 Track Router，只归线不写 Event；上海时间凌晨三点后，对待结算材料按每条 primary Track 的有界 corridor 调用 Curator；Router 声明的 bridge 只把直接 unit 共享给相邻 Track，不会把两条 Track 的整段历史并成一组。对每条拟写 Event 调用一次 Event Writer。未在白天归线的材料，结算时可能先调用 Router。没有合格的新材料就不会发起对应阶段请求。

自动摘要每次从关闭改为开启时，把当时已有的最后一条原话设为新边界；此前尚未整理的原话只保留在原话档案，不补跑模型。关闭期间的新原话也一样保留，重新开启后从新的边界继续。已开启时保存其他设置不会移动边界。

实际次数由批次、关联组、拟写 Event 及图片决定。Curator 和 Writer 各可因前情不足再请求一次；Writer 补读遇到图片可能另调用 Curator 转录。模型已返回但格式、长度或证据校验失败时，单次执行最多补两次纠错请求；上游报错、超时或最终校验失败会留下未完成任务。自动整理仍开启时，后台约每 30 秒再检查并可能重新调用同一阶段，不能把单次的三次请求上限当成总上限；持续失败可能持续计费，需先关闭自动摘要并检查失败记录和模型配置。完成的阶段结果会保留。建议 Event Writer 使用理解上下文和写作能力较强的模型，以处理人物归属、因果、修订和细节取舍。保存 Event 后，另有已启用的打标或 Embedding 索引任务可能调用对应模型。关闭自动摘要停止定时整理，但手动继续及其他功能仍可能调用模型。

- API：三个语义阶段都需要已配置的模型，远程上游需要密钥。未选择独立图片转录模型时，切分与 Writer 使用图片内容块及 JSON 输出；选择后，图片转录模型需支持图片和 JSON，切分器读取已落库的文字。
- Agent：由用户已安装、已认证的执行器连接 `scripts/event_agent_mcp.py`，领取任务并提交结果。图片通过 MCP image content 返回。阶段模型字段作为执行提示，由执行器按自身支持的模型选择执行；网页不会安装或启动私有 CLI，也不会继承其他机器的登录状态。
- 升级前未设置执行方式的实例保留按阶段选择 API/Agent 的兼容行为，直到用户明确切换。旧客户端保存其他设置不会清掉 Event 配置。新客户端保存时校验设置版本，冲突后需刷新核对。

一轮执行开始时冻结三阶段模型、身份和超时。运行中修改设置不影响该轮；下一轮继续任务时读取新配置，已完成步骤保留。模型凭据只在服务端内存中使用，不放进 Agent 任务或浏览器响应。切换不重跑已完成 Event、不修改结算游标。

“每批原话字符上限”用于 transport 分批，不截断完整回复包。若单个完整回复包本身超过该值，它会独占一批；后续材料仍按上限继续拆分。降低此值后，下一次继续整理会用当前设置重新检查尚未结算的冻结批次：判断依据是 Router/Curator 实际读取的 `routing_messages`，而不是只看 stable `messages`；如果新上限确实能把冻结材料拆成更小批次，旧批次会保留历史任务并置为 `superseded_input_budget`，原话重新按新上限领取，已接受的 Router 结果仍按既有恢复规则保存。

“完整提示词字符上限”是模型调用前最后一道保护，默认仍为 40000，但可按所用模型的上下文能力调到 4000000。这个值不是批次输入快照：提高后，下一次继续同一冻结批次就会读取新值，不需要先重建。超过上限时原话仍不截断，错误会明确区分“提高提示词上限”与“降低输入上限后重批”两条出路。

Event Writer 可在“自动摘要配置”中设置首轮并发数 1–8，默认 1。只在 Curator 已经冻结本批 Event 计划后并发第一轮 Writer；Router、Curator、Track 状态推进、Writer 的 bounded context 补读/图片转录和最终 settlement 仍保持串行。Agent 执行方式始终一次领取一个 Writer 任务；API 或宿主提供的内联 runner 才会使用大于 1 的并发。并发结果按 Curator 原 ordinal 汇总，落库顺序不按请求完成先后改变；某个 Writer 失败时，已完成并持久化的兄弟 job 保留，未完成任务可在继续整理时恢复。

## 材料和保护

按单条原始消息归线，每条恰好一个主 Track。完整问答只用于传输分批和判断未完成尾部，不强制同一轮所有消息归同一线。Curator 的 stable unit 是单条消息，消息本身不可拆。原文覆盖、Router 声明的 bridge 和已有 Event 保护都由程序校验。bridge 只允许对应的直接 unit 进入两条 Track corridor，不能借此读取或合并另一条 Track 的其他历史与 base Event。受保护提案只在当前 corridor 内按实际共享 unit 传播暂缓；独立提案继续处理。原本非法的重复归属不会因保护触发而通过校验。

extend/merge 的输入保留所有所选前版正文及其绑定原文，与新原文一起提供。前版正文用于检查遗漏，不能代替原始证据。新的规则不会自动修复历史正文，也不会解除旧条保护。修订来源和保护来源的进一步区分不包含在本次改动中。

自动 Event 只按绑定原文判断入选和正文取舍，不再读取已有 Scene 来跳过或省略经历。Scene 的编辑、解绑或新增不会单独使 Event 任务失效；主动保存 Scene、按原文精确查找 Scene 的接口，以及被 Scene 引用的旧 Event 保护继续保留。

升级后，尚未完成的旧协议批次会重新生成任务，避免继续使用按 Scene 省略过的旧提案。原话和历史任务记录保留；已完成的 Event 和原话处理状态不变。

Writer 规则保留一则组织内容的短正例，三则“原文 → 错写 → 错因 → 正写”的合成对照。以原文锚点和最小完整语义单位组织正文，保留人物、否定、限定、比喻与计划状态；不因局部回应而截掉前句的完整意思，也不补出理解、确认或执行动作。归属依原文与回应关系保留，不指定某一种归属句式。技术闲聊的 `recallable` 一律为 false，包含工程进度、决定或约束也不例外；这不阻止有实质展开的技术经历生成 Event。输出格式由任务提示统一提供，分别说明证据充分与不足的返回形式。

图片转录模型由使用者在设置中选择，公开版不内置供应商、模型或密钥。配置了独立转录模型时，每次请求只发一张缺失图片，逐张保存成功结果；某张失败不抹掉其他图片的转录，继续任务时只补缺项。未配置独立转录模型时保留原有 Curator 看图兼容模式。

转录用 [文字] 保留图片中可见的标题、正文、评论，用 [画面] 简述可见人物、物件、布局和关系；没有文字也保留画面描述，不推断身份、动机或前后经过，不可辨认处明确标记。模型只能提供图片序号、文字与 unreadable，程序绑定真实消息 ID、图序、SHA-256 和阅读角色。每图必须恰有一份转录，重复、遗漏或自报出处均被拒绝。独立转录写入原始消息同行的 `image_transcription_status`、`image_transcription_json`、`image_transcription_updated_at`；缓存按单图成功及 SHA-256、图序匹配复用，同一消息仍有失败图片也不妨碍复用成功项。历史 Curator 已保存的准确绑定转录同样可复用，角色按本次阅读范围重新绑定。

Writer 只读取按原图字节验证的转录与可见画面描述，初写及修复重试都不接收原图。缺漏、过期或阅读范围错误的转录在调用前被拒绝。context_only 图片与文字不扩大归属。Curator 和 Writer 分别至多请求一次有界补读：程序只读指定 Track、允许会话和给定边界前的最多六条原始消息。Writer 补读带来的图片另外转录，不重新决定 Event 边界。事件使用的转录收据另保存在 `pipeline_event_details.details_json.curator_image_transcriptions`；原始消息同行列是可复用事实来源，不创建独立摘要表。

公开版直接使用导入附件里的图片数据或公开 HTTP(S) 原图地址，不扫描宿主会话目录。远程图像最多跟随三次标准重定向；每一跳都重新校验域名解析并固定连接到已验证的公网 IP，拒绝内网目标、循环及 HTTPS 降级。单图上限 10 MB，每批最多 24 张、40 MB，超出时要求减小批次，不静默截断。

任务快照不再把同一份原话、候选正文和图片字节层层复制到 batch、component 与 job JSON。未完成任务所需的冻结图片字节只在 `pipeline_media` 保存一份，任务 JSON 仅保存消息位置与 SHA-256；实际调用 API 或 Agent 时再临时还原。任务成功结算后立即删除这份冻结字节，并把下游请求收缩成摘要与校验哈希；Router 的恢复证据仍保留。升级时也会一次性收缩既有的已完成任务快照。

原话档案中的附件属于原始存档，不随任务快照清理；已保存的转录文字也保留。这里没有通用上传文件池，不把其他宿主的文件清理规则当作已实现功能。

## 人工核对

自动摘要可能切分不当、遗漏细节、判断错重点，或混淆引用出处、人物归属和原话的确定程度；图片识别也可能出错。重要内容请结合原始对话核对并按需修订。部分材料会因上下文未结束、已有内容受保护或模型服务失败而暂未生成。

流水线显示失败记录、跳过及保护暂缓情况。Event 列表支持多选、全选当前筛选、归档、取消归档、不自动浮现和确认删除。只按服务端回执更新；失败项保留选择。取消归档不恢复已关闭的自动浮现资格。删除确认包含数量及不可撤销含义，并按回执处理整个修订家族；原话档案保留。

模型自报 self_review 不能证明语义准确率。程序保留结构、证据与来源校验。Writer 被明确要求把 Event 正文控制在 1000 字以内；1000 是写作硬上限而非目标，短经历写清即停，不得为了接近上限补内容。为容忍不同模型的字符计数误差，host 以 1500 字作为异常拒绝阈值：超过 1500 会进入原有纠错流程，仍超长则拒绝落库；程序不截断正文。Writer 应优先保留不可替代的原话锚点、辨识细节、真实转折、关键因果、承诺条件与实际落点，删除旁支、逐轮复述、并列堆例和重复说法；extend/merge 不照搬旧稿，也不能因压缩删掉前版经历中不可替代的转折和结果。不按特定措辞拒稿；没有准确率数字或完全保真的承诺。

## Track 跨批次续接

白天自动归线保留两个同时满足的门槛：同一 session 的待处理材料累计至少五个已完成回复包，并在最后一条可回应消息后形成二十分钟会话静默。不同 session 不合计；不足五个会留到后续累计。这里的“二十分钟”不是只看使用者最后一次发言：助手发出的普通回复或主动消息也属于可回应消息，会从自己的发出时间重新开启回应窗口。

具体情况如下：

| 到达情况 | 回复包与计时 | 白天归线结果 |
| --- | --- | --- |
| 使用者发言，助手完成回复 | 形成一个完整回复包；从该包最后一条消息重新计时 | 同一 session 累计至少五个且静默满二十分钟后可归线 |
| 使用者提问后尚无助手回复 | 尾部不完整，不凑轮数；这条提问仍开启回应窗口 | 满二十分钟后，前面已经完整且达到五个的部分可以先归线，未完成提问继续等待 |
| 助手主动发出消息，使用者尚未回复 | 不凑轮数；主动消息重新开启二十分钟回应窗口 | 窗口内继续等待；满二十分钟后，前面已经完整且达到五个的部分可以先归线，主动消息继续作为未完成尾部 |
| 助手主动消息得到使用者回复 | 主动消息、首条使用者回复及随后属于该次交互的落点合为一个回复包，只计一次 | 从该包最后一条消息重新计时；满足累计门槛后可归线 |
| 使用者回复前连续到达多条主动消息 | 合为一个待回应包，不按消息数增加轮数 | 最近一条主动消息会把回应窗口继续向后推；不会凭这些消息凑满五个 |
| 持续对话，中间没有二十分钟停顿 | 即使较早的五个回复包都已超过二十分钟，也尚未出现真实静默 | 不提前归线 |
| 长对话中间已经停顿二十分钟，之后又开始聊天 | 停顿形成可处理截点 | 停顿前的完整部分可先归线，最近仍活跃的尾部继续等待 |
| 助手的迟到回复先于其原始提问抵达当前持久账本 | 为避免阻塞后续材料，按一个可处理回复包读取 | 仍结合已有 Track 判断归属，不凭到达顺序推断 Event 边界 |

白天 Router 只接收已经满足上述条件的完整回复包。凌晨结算时，尚未完成的尾部可以作为 parked 上下文进入同一粗分批次：Router 仍逐条查看并为其归 Track，但 Curator 不把 parked 尾部当成本轮稳定来源。因而“二十分钟未获回应”只决定批次和稳定／parked 状态，不会绕过 Track，也不会直接把这一处切成 Event 边界。

白天只保存 Track 和消息归属，不生成 Event，也不把原话标成已结算。Event 仍在上海时间凌晨三点结算；手动 include_recent 继续保留处理近期完整对话的入口。二十分钟用于判断输入稳定和粗分传输批次，不是结束 Track 的条件。

归线行为对照线上运行的 Bridge 提交 5470a1b 核实。Track 卡不设按时间删除的期限。每个批次沿用同一来源、同一 runtime／workspace 边界下当前窗口和上一个可见窗口的 Track：先将旧 active 卡暂置 parked，再按本批实际使用恢复或更新。未使用的卡仍保留在最后实际出现的窗口，不因时间删除，也不移动到当前窗口；当该窗口不再属于“当前＋上一个可见窗口”的范围时，这些卡退出 Router 的默认可见范围，但仍留在数据库中。本批再次使用的卡会把最近窗口更新为当前窗口，因此可以继续向后承接。

卡片保存初始窗口、最近窗口和最近原话编号；下一批从真实原文恢复锚点。优先取最近主归属消息，仅作为 context 的 Track 使用最近桥接消息。旧卡缺少锚点时从已有归线记录补出，不改写已结算 Event。编号按当前窗口已有最大序号递增，跨窗续接保留原 ID。rolling_engineering 只能继承，不能降级。

公开导入的窗口编号可能不是数字，窗口顺序使用同一来源的首次可见消息；保留 metadata.runtime / workspace_root 隔离。若原始 metadata 带 previous_session_id，则以该显式承接为准；没有时采用相同来源和环境的上一可见窗口。不根据话题相似度虚构承接。

旧协议尚未结束的任务保留为 superseded_protocol，未处理原话按新协议重新领取；已结算原话、Event 和归线记录保留。
