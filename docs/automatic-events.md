# 自动 Event

## 从网页开始

1. 在“设置 → 模型”添加上游和模型，保存。
2. 在“设置 → 配置 → 自动摘要配置”选择执行方式、阶段模型、输入量、超时和可选开关。
3. 在“设置 → 功能”开启自动摘要；从关闭改为开启会从新的原话边界开始。需要整理边界外的旧积压时，到“原话整理”查看数量，点“恢复并整理这批原话”。
4. 在“设置 → 对话导入 → 原话整理”看进度或手动继续；历史文件默认归档，需要时在导入完成后明确加入整理。

## 失败后怎么继续

| 页面情况 | 如何处理 |
| --- | --- |
| 文字步骤累计失败三次 | 检查原因，点“重试此批次”；成功步骤复用。同一聊天等待，其他聊天继续 |
| Curator 漏掉 stable 原话的去向 | 同一任务纠正一次；仍漏则由程序记录漏掉的原话 ID，保留整个审阅范围，次日再检查。本日不反复请求该范围，其他独立范围继续结算；同一范围累计三轮仍漏时暂停，可检查输出后重试该批次 |
| 图片转录失败三次 | 点“重试这张图片”重新开放三次机会；成功图片和独立文字继续，依赖失败图片的活动暂存 |
| 原图无有效地址或返回 404/410 | 跳过附件，保留文字和其他可用图片，不猜补图片内容 |
| 归线材料待修复 | 先“重新校验并继续”，确实无法恢复时明确确认“作废本批计划并重新归线” |
| 等待 Agent | 让执行器领取、提交当前任务；等待本身不算失败 |
| 提示词超限或原图下载暂时失败 | 按提示调整输入／提示词上限或检查连接；超时、403/5xx、冻结材料损坏不会当作缺图跳过 |
| 开启自动摘要时已有原话被划到边界外 | “原话整理”显示数量；确认“恢复并整理这批原话”后，只将 `auto_boundary` 原话重新放入待整理池，并启动一次后台整理。已结算和主动跳过的原话不重跑 |

手动重试可能产生费用。三次预算属于某个文字步骤或某张图片，不是实例总调用上限。归线恢复详见 [归线历史恢复](route-recovery.md)。

## 来源与正文

Curator 的 `decision_review` 记录每条拟议 Event 的活动依据、同一 Track 相邻 Event 边界两侧各自独占的逐字原文，以及 skip/defer 的完整处置理由。直接 defer 必须指向本轮真实 parked 原文 ID。host 在既有 exact-cover、bridge 和受保护前版校验之外核对回执；默认暂缓受保护来源。Writer 可额外返回 `claim_groups` 与 `sentence_evidence`；返回时 host 核对其中的 owned 来源、逐字引文和正文对应关系，收据随 writer detail 保存，不改变正式 Event 的字段。未返回收据时，由冻结的 ownership 限定 Writer 可用材料，host 不声称已逐句证明正文语义。重要内容仍需对照原话人工复核。

Curator 的漏项仅指本轮 stable 原话既未进入 Event，也未明确列入 skip/defer；明确 skip 的旁支属于正常取舍。首次漏项后，纠错请求保留完整审阅材料和上一份结果，并单列遗漏原话正文及编号，要求补全后提交完整 JSON，重新校验来源与冲突。纠正一次仍漏则暂停当前冻结批次，不再留池重新组批；手动重试沿用原材料和已完成阶段。修复材料超过提示词上限时同样暂停，不截断材料。

这次输出回执属于新的流水线协议。升级前尚未结束的旧协议任务标记为 `superseded_protocol`，未结算原话按新协议重新领取；已结算 Event、原话状态和旧任务记录不改写。

桥接来源改为显式归属后，流水线协议升至 v8。仍在处理的 v7 批次按上述规则重新领取原话，避免用新校验重新解释旧版已冻结的 Curator 决定。

公开版不会从消息相邻关系猜测回复目标。开启轮次门槛后，若元数据明确提供 reply_to_user_message_id，会核对助手是否回复本轮拥有的用户消息；回复另一条用户消息的组合不算完整轮次。无该字段时沿用角色与完整来源计算。来源时间换算为 Asia/Shanghai。Writer 通常以 500 字为软预算，复杂经历可超出；程序以 1500 字为异常拒绝阈值。

Router 以消息实际新增并被后续接住的对象或活动归线，不按醒目称呼、重复关键词或从事实转为玩笑的语气变化改线。Writer 若直接保留使用者引语，正文应给出最小说话人归属；引语结束后切回叙述应有标点。返回逐句收据时，host 会据此做结构校验。受保护旧 Event 默认保持暂缓；开启“受保护 Event 后续追加”后，仅允许对可信、活动中的单个前版追加新段落，原有标题、正文和召回设置原样保留。

自动整理采用归线 → 切分 → Event 写作三个语义阶段。图片转录是独立、逐图可复用的材料任务：优先使用“图片转录”模型；未选择时使用切分模型执行同样的转录任务，该模型仍需视觉能力。Curator 和 Writer 读取转录，Writer 不接收原图。Event 直接保存；可另选“Event · Arc 归档”模型归入已有叙事卷，也可开启“Event 升为 Scene”让主窗口主动编辑保存。

## 可选的 Arc Linker

`Event Writer → 正式 Event → 自动归入已有叙事卷`。Event 结算完成后，程序只用它的标题和正文在活动 Arc 的标题、别名、实体和检索词中做关键词预检索，再把有界候选交给 Arc Linker。Linker 只能选一条已有 Arc 或返回不归属；不创建 Arc，不写叙事正文，不读 Event 绑定的聊天原话或叙事卷正文。

Arc Linker 直接根据 Event 内容与 Arc 卡判断，不等待、不使用打标模型抽取的 `tagged_entities`。关键词没有命中任何 Arc 时不调用模型；模型或格式失败时 Event 仍已正常落库，只保持未归属。这是落库后的可选任务，不改变前面三阶段的结算成功与否。

升级时忽略旧的 `event_evidence` 模型选择；旧页面提交该字段仍可保存其他配置。停在该阶段的任务继续时直接进入 Writer，已完成的归线、切分及历史回执保留；历史 Event 的旧证据整理结果不删除。

公开版聊天代理在收到成功回复后，把当前用户原话和完整助手正文写入消息库，使用已有的原话编号、搜索与流水线待处理入口。流式响应必须正常结束；工具调用阶段只保存用户原话，最终正文回来后补齐助手消息。系统提示、推理、工具返回和注入材料不作为原话归档，图片保留材料引用。关闭自动摘要或记忆召回不影响原话保存。

客户端应传稳定的 `serein.window_id` 或 `X-Serein-Window-Id`。重试和工具续轮按窗口及原始对话去重；提供消息 `id` / `message_id` 时，裁剪历史后仍可识别同一消息。没有消息 ID 的客户端若同时改变历史，无法可靠识别其是否为旧请求；不同窗口也不应共用默认的 `main`。时间记录为代理接收/回复完成时间，不伪造历史消息时间；不会自动补录请求携带的旧聊天。入库失败或内容被拒绝会记在请求诊断的 `raw_archive` 中，不丢弃已经生成的回复。

自动摘要开关在设置 → 功能中，保存后生效。点击“自动摘要配置”跳转到配置页，选择执行方式和参数。三个语义阶段分别为归线、切分、Event 写作，也在“配置”页选择模型；图片转录可另选模型并在聊天与自动摘要之间复用。“模型”页管理上游地址、密钥和模型目录；打开时直接显示已配置上游，各上游里的模型和编辑项默认收起。

打开开关不会立刻或每轮固定调用三个模型。聊天成功后先保存原话；历史文件默认只归档，可在导入完成后明确加入整理。白天同一会话至少五个已完成回复包并静默二十分钟后调用 Router，只归线不写 Event；上海时间凌晨三点后对待结算 Track 调用 Curator。默认分开审阅；开启联合审阅时，明确 bridge 可连接同一会话中最多三条 Track 一起核对。Writer 对拟写 Event 生成正文。手动继续可立即处理完整材料，没有合格材料不调用相应阶段。

自动摘要每次从关闭改为开启时，把当时已有的最后一条原话设为新边界；此前尚未整理的原话只保留在原话档案，不补跑模型。关闭期间的新原话也一样保留，重新开启后从新的边界继续。已开启时保存其他设置不会移动边界。

实际调用次数由批次、审阅范围、Event 和图片决定。Curator 与 Writer 各可因前情不足补读一次。API 结构错误可以纠错，但同一文字 job 的失败跨执行累计三次后暂停所属批次；继续不会清零。成功阶段及兄弟 Writer 结果保留，手动重试从失败步骤恢复。“继续整理”绕过暂停批次处理其他聊天，同一 source/session 的后续材料等待恢复。日间只归线、调用前配置／输入错误、Agent 等待不适用此预算。打标、Embedding 和 Arc Linker 等任务也有各自调度，不共用此预算。

- API：配置各阶段模型与必要密钥。图片转录模型（或回退的切分模型）需支持图片和 JSON；Curator 与 Writer 的正常整理任务读取文字和转录，不附原图。
- Agent：由用户已安装、已认证的执行器连接 `scripts/event_agent_mcp.py`，领取任务并提交结果。图片通过 MCP image content 返回。阶段模型字段作为执行提示，由执行器按自身支持的模型选择执行；网页不会安装或启动私有 CLI，也不会继承其他机器的登录状态。
- 升级前未设置执行方式的实例保留按阶段选择 API/Agent 的兼容行为，直到用户明确切换。旧客户端保存其他设置不会清掉 Event 配置。新客户端保存时校验设置版本，冲突后需刷新核对。

一轮执行开始时冻结三阶段模型、身份和超时。运行中修改设置不影响该轮；下一轮继续任务时读取新配置，已完成步骤保留。模型凭据只在服务端内存中使用，不放进 Agent 任务或浏览器响应。切换不重跑已完成 Event、不修改结算游标。

“每批原话字符上限”用于 transport 分批，不截断完整回复包。若单个完整回复包本身超过该值，它会独占一批；后续材料仍按上限继续拆分。降低此值后，下一次继续整理会用当前设置重新检查尚未结算的冻结批次：判断依据是 Router/Curator 实际读取的 `routing_messages`，而不是只看 stable `messages`；如果新上限确实能把冻结材料拆成更小批次，旧批次会保留历史任务并置为 `superseded_input_budget`，原话重新按新上限领取，已接受的 Router 结果仍按既有恢复规则保存。

“完整提示词字符上限”是模型调用前最后一道保护，默认为 200000，但可按所用模型的上下文能力调到 4000000。 每批新原文的默认目标为 40000 字符；未保存这两个字段的实例使用新默认值，已保存的配置保持原值。这个值不是批次输入快照：提高后，下一次继续同一冻结批次就会读取新值，不需要先重建。超过上限时原话仍不截断，错误会明确区分“提高提示词上限”与“降低输入上限后重批”两条出路。

Event Writer 可在“自动摘要配置”中设置首轮并发数 1–8，默认 1。只在 Curator 已经冻结本批 Event 计划后并发第一轮 Writer；Router、Curator、Track 状态推进、Writer 的 bounded context 补读/图片转录和最终 settlement 仍保持串行。Agent 执行方式始终一次领取一个 Writer 任务；API 或宿主提供的内联 runner 才会使用大于 1 的并发。并发结果按 Curator 原 ordinal 汇总，落库顺序不按请求完成先后改变；某个 Writer 失败时，已完成并持久化的兄弟 job 保留，未完成任务可在继续整理时恢复。

“自动摘要配置”另有四个默认关闭的选项，只影响新冻结的批次。**跨线联合审阅**只把同一会话中由稳定、明确 bridge 连接的最多三条 Track 放进同一 Curator 阅读范围；合并为一个 Event 需要两侧和桥接原文的逐字证据，未满足边界时继续分开。**逐条材料取舍**要求 Curator 对每个 Event 的全部 owned 原话标明 main、background、omit 或 mixed；mixed 的省略片段必须逐字有效。原话及 ownership 不会被删，Writer 只按这些用途取材。**普通交流轮次门槛**在 Curator 冻结边界后计数：至少两轮完整的用户与助手交流才进入 Writer；未结束的短段等待新原话，原文明确结束的短段跳过。分气泡和纯背景不能凑轮。**受保护 Event 后续追加**只处理由流水线创建、仍为活动叶子且仅因既有引用受保护的单个 Event；Writer 只写新原话的后续段落，程序原样保留旧正文并附加新段落。校验拒绝重写旧标题、正文、召回设置或遗漏旧来源。四个选项关闭时沿用原有任务协议；修改配置不重写已冻结的任务或已有 Event。

## 材料和保护

按单条原始消息归线，每条恰好一个主 Track。完整问答只用于传输分批和判断未完成尾部，不强制同一轮所有消息归同一线。Curator 的 stable unit 是单条消息，消息本身不可拆。原文覆盖、Router 声明的 bridge 和已有 Event 保护都由程序校验。bridge 只允许对应的直接 unit 进入两条 Track corridor，不能借此读取或合并另一条 Track 的其他历史与 base Event。受保护提案只在当前 corridor 内按实际共享 unit 传播暂缓；独立提案继续处理。原本非法的重复归属不会因保护触发而通过校验。

联合审阅中，Router 的 bridge 只提供共同审阅范围，不由程序自动补成另一侧 Event 的来源。若两侧都形成 Event，Curator 须显式选择完整 bridge unit；仅共享对象或背景而不归入某侧时，`decision_review.bridge_exclusions` 记录被排除的 Track、理由和 bridge 内逐字证据。实际回应、拒绝、纠正或收尾应保留在对应 Event。单条消息同时含重要决定与无关提醒时，逐条材料取舍用 `mixed` 和逐字 `omit_quotes` 标出旁支，不因保留整条来源就把旁支写入正文。

Curator 审阅 extend/rewrite/merge 时保留所选前版正文及其绑定原文，与新原文一起核对；Writer 普通 extend 只接收旧正文背景和新增原文，明确 rewrite/merge 才读取所选前版的相关旧原文。前版正文用于检查遗漏，不能代替原始证据。新的规则不会自动修复历史正文；默认不解除旧条保护，受保护后续追加仅在明确开启且满足校验时生效。修订来源和保护来源的进一步区分不包含在本次改动中。

自动 Event 只按绑定原文判断入选和正文取舍，不再读取已有 Scene 来跳过或省略经历。Scene 的编辑、解绑或新增不会单独使 Event 任务失效；主动保存 Scene、按原文精确查找 Scene 的接口，以及被 Scene 引用的旧 Event 保护继续保留。

升级后，尚未完成的旧协议批次会重新生成任务，避免继续使用按 Scene 省略过的旧提案。原话和历史任务记录保留；已完成的 Event 和原话处理状态不变。

Writer 围绕当前经历组织正文，保留必要归属、条件、否定、比喻与真实时序。纠正后直接写最终结论，不逐次报幕纠正和撤回动作；只有省略时间会误导时才补提示。不补写未表达的感受、因果或关系意义，续接保留早期重要内容。正文可以压缩改写，证据引文的出处校验不要求正文照抄。Writer 不判断 recallable，程序按“地下室 → 主域边界”的 Event 规则决定是否允许浮现，并保留手动关闭、归档、覆盖、证据与冷却限制。规则更新不自动重写历史正文。

Writer 普通接续（extend）只读旧 Event 正文作为背景与真正新增的 owned 原文，只生成新段落；程序原样保留旧标题、正文和召回设置，再拼接新段落。默认没有附带原文上下文，旧绑定原文、旧图片转录及旧材料清单不发送；仅明确请求的定向补读可提供最多六条、合计 6000 字符的上下文，仍排除已有 Event 的绑定原文。明确整篇重写（rewrite）或多 Event 合并（merge）才读取所选前版的相关旧原文，不读取其他旧卡的历史。Curator 仍核对旧绑定原文，程序保存时仍继承完整来源绑定；全旧来源整 unit 暂缓，不调用 Writer、不生成新 Event、不新增处理标记。尚未完成的旧 Writer 请求在继续时按同一冻结计划采用新写作方式，已完成结果保留原有整篇或追加语义，不重跑、不二次拼接。Agent 领取的 Writer JSON 也只包含模型所需的阅读材料，完整来源并集留在 host 快照。

整篇 Event 总计上限仍为 1500 字符，包含旧正文、新增段落及拼接的两个换行。Writer 按剩余字符额度生成新增段落，超出则进入既有纠错流程；存储层仍拒绝超限正文，绝不截断旧正文。旧正文没有剩余空间时，不调用 Writer，明确重建计划后可选择整篇 rewrite。

图片转录模型由使用者配置，公开版不内置模型或密钥。每次只附一张待转录图片，成功结果逐张保存；某张失败不抹掉其他图片，后续只补缺项。未选独立模型时回退到切分模型执行转录任务，仍需视觉能力。

转录用 [文字] 保留图片中可见的标题、正文、评论，用 [画面] 简述可见人物、物件、布局和关系；没有文字也保留画面描述，不推断身份、动机或前后经过，不可辨认处明确标记。模型只能提供图片序号、文字与 unreadable，程序绑定真实消息 ID、图序、SHA-256 和阅读角色。每图必须恰有一份转录，重复、遗漏或自报出处均被拒绝。独立转录写入原始消息同行的 `image_transcription_status`、`image_transcription_json`、`image_transcription_updated_at`；缓存按单图成功及 SHA-256、图序匹配复用，同一消息仍有失败图片也不妨碍复用成功项。历史 Curator 已保存的准确绑定转录同样可复用，角色按本次阅读范围重新绑定。

Writer 只读取按原图字节验证的转录与可见画面描述，初写及修复重试都不接收原图。缺漏、过期或阅读范围错误的转录在调用前被拒绝。context_only 图片与文字不扩大归属。Curator 和 Writer 分别至多请求一次有界补读：程序只读指定 Track、允许会话和给定边界前的最多六条原始消息。Writer 补读带来的图片另外转录，不重新决定 Event 边界。事件使用的转录收据另保存在 `pipeline_event_details.details_json.curator_image_transcriptions`；原始消息同行列是可复用事实来源，不创建独立摘要表。

公开版直接使用导入附件里的图片数据或公开 HTTP(S) 原图地址，不扫描宿主会话目录。远程图像最多跟随三次标准重定向；每一跳都重新校验域名解析并固定连接到已验证的公网 IP，拒绝内网目标、循环及 HTTPS 降级。单图上限 10 MB，每批最多 24 张、40 MB，超出时要求减小批次，不静默截断。

任务快照不再把同一份原话、候选正文和图片字节层层复制到 batch、component 与 job JSON。未完成任务所需的冻结图片字节只在 `pipeline_media` 保存一份，任务 JSON 仅保存消息位置与 SHA-256；实际调用 API 或 Agent 时再临时还原。任务成功结算后立即删除这份冻结字节，并把下游请求收缩成摘要与校验哈希；Router 的恢复证据仍保留。升级时也会一次性收缩既有的已完成任务快照。

原话档案中的附件属于原始存档，不随任务快照清理；已保存的转录文字也保留。这里没有通用上传文件池，不把其他宿主的文件清理规则当作已实现功能。

## 人工核对

自动摘要可能切分不当、遗漏细节、判断错重点，或混淆引用出处、人物归属和原话的确定程度；图片识别也可能出错。重要内容请结合原始对话核对并按需修订。部分材料会因上下文未结束、已有内容受保护或模型服务失败而暂未生成。

流水线显示失败记录、跳过及保护暂缓情况。Event 列表支持多选、全选当前筛选、归档、取消归档、不自动浮现和确认删除。只按服务端回执更新；失败项保留选择。取消归档不恢复已关闭的自动浮现资格。删除确认包含数量及不可撤销含义，并按回执处理整个修订家族；原话档案保留。

`self_review` 对象仍按输出格式提供，但其中的自报布尔值不作为拒收条件，也不能证明语义准确率。Writer 无须返回 claim_groups 或 sentence_evidence；若额外返回，程序仍校验其中的 owned 来源与逐字引文。程序保留标题、正文、证据充分性和冻结来源绑定检查。Writer 正文通常控制在 500 字以内，不必写满；复杂经历可适当超出。host 以 1500 字作为异常拒绝阈值：超过 1500 会进入原有纠错流程，仍超长则拒绝落库；程序不截断正文。Writer 应优先保留不可替代的原话锚点、辨识细节、真实转折、关键因果、承诺条件与实际落点，删除旁支、逐轮复述、并列堆例和重复说法；extend/merge 不照搬旧稿，也不能因压缩删掉前版经历中不可替代的转折和结果。不按特定措辞拒稿；没有准确率数字或完全保真的承诺。

## Track 跨批次续接

白天自动归线保留两个同时满足的门槛：同一 session 的待处理材料累计至少五个已完成回复包，并在最后一条可回应消息后形成二十分钟会话静默。不同 session 不合计；不足五个会留到后续累计。这里的“二十分钟”不是只看使用者最后一次发言：助手发出的普通回复或主动消息也属于可回应消息，会从自己的发出时间重新开启回应窗口。

具体情况如下：

| 到达情况 | 回复包与计时 | 白天归线结果 |
| --- | --- | --- |
| 使用者发言，助手完成回复 | 形成一个完整回复包；从该包最后一条消息重新计时 | 同一 session 累计至少五个且静默满二十分钟后可归线 |
| 使用者提问后尚无助手回复 | 尾部不完整，不凑轮数；这条提问仍开启回应窗口 | 满二十分钟后，前面已经完整且达到五个的部分可以先归线，未完成提问继续等待 |
| 助手主动发出消息，使用者尚未回复 | 不凑轮数；主动消息重新开启二十分钟回应窗口 | 窗口内继续等待；满二十分钟后，前面已经完整且达到五个的部分可以先归线，主动消息继续作为未完成尾部 |
| 助手主动消息得到使用者回复 | 主动消息、首条使用者回复及随后属于该次交互的落点合为一个回复包，只计一次 | 从该包最后一条消息重新计时；满足累计门槛后可归线 |
| 使用者回复前连续到达多条主动消息 | 合为一个待回应包，不按消息数增加轮数 | 最近一条主动消息会把回应窗口继续向后推；不会凭这些消息凑满五个 |
| 持续对话，中间没有二十分钟停顿 | 即使较早的五个回复包都已超过二十分钟，也尚未出现真实静默 | 不提前归线 |
| 长对话中间已经停顿二十分钟，之后又开始聊天 | 停顿形成可处理截点 | 停顿前的完整部分可先归线，最近仍活跃的尾部继续等待 |
| 助手的迟到回复先于其原始提问抵达当前持久账本 | 为避免阻塞后续材料，按一个可处理回复包读取 | 仍结合已有 Track 判断归属，不凭到达顺序推断 Event 边界 |

白天 Router 只接收已经满足上述条件的完整回复包。凌晨结算时，尚未完成的尾部可以作为 parked 上下文进入同一粗分批次：Router 仍逐条查看并为其归 Track，但 Curator 不把 parked 尾部当成本轮稳定来源。因而“二十分钟未获回应”只决定批次和稳定／parked 状态，不会绕过 Track，也不会直接把这一处切成 Event 边界。

白天只保存 Track 和消息归属，不生成 Event，也不把原话标成已结算。Event 仍在上海时间凌晨三点结算；手动 include_recent 继续保留处理近期完整对话的入口。二十分钟用于判断输入稳定和粗分传输批次，不是结束 Track 的条件。

公开版归线不依赖上游 API 提供聊天窗口身份。每个批次读取同一来源、同一 runtime／workspace 边界下，在配置回看天数内实际归入过原话的 Track；默认三天，按本批第一条原话与旧 Track 最后一次已保存归线原话的时间差判断。先将旧 active 卡暂置 parked，再按本批实际使用恢复或更新。超期卡不送入 Router，但仍保留在数据库中；本批再次使用的卡更新最近归线锚点，以便后续短期承接。

卡片保存初始会话、最近会话和最近原话编号；下一批以真实已保存归线记录恢复锚点，主归属与 context 归属都算实际使用。没有可核对归线记录的卡不凭窗口位置自动入选；不改写已结算 Event。编号按当前会话已有最大序号递增，跨会话续接保留原 ID。rolling_engineering 只能继承，不能降级。

公开导入的会话编号可以是不透明字符串；归线只依赖原话时间、来源和已有归线记录，保留 metadata.runtime / workspace_root 隔离。previous_session_id 不再决定 Track 的可见范围；不根据话题相似度虚构承接。

旧 Event 不按 Track 回看天数过期。同一 Track 最多完整读取 8 条 active leaves；出现第 9 条时，host 不截断候选，也不调用 Curator 或 Writer，而是把该 Track 本轮稳定原话 defer，等待人工处理误归线、归档不再需要的叶子或安全合并。其他 Track 不受影响。Event 本身不会因此被归档或退出召回。

旧协议尚未结束的任务保留为 superseded_protocol，未处理原话按新协议重新领取；已结算原话、Event 和归线记录保留。

归线候选检索为可选实验，默认关闭，仍完整带入回看范围内的旧 Track 卡。开启后，最近 12／24／48／72 小时有活动的卡直接带入，较早卡由程序使用整批新原文与附近前文进行 jieba＋BM25 检索，默认补充最多 8 张（可设 1～50）。搜索短标题、续接线索及近期原文，过滤保守口头停用词；先排除直接带入卡，再合并去重，候选按最近活动时间排列。检索仅筛选本次 Router 输入，不删除或截断存储中的卡片和原文，不自动回改以前的消息归属。检索可能漏接或改变分线；已冻结任务保持原输入和配置。
